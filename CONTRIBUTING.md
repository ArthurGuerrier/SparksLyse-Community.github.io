# Guide de contribution

Merci de votre intérêt pour la contribution à ce projet.

## Avant de commencer

- Consultez les issues ouvertes avant de créer une nouvelle proposition.
- Pour un changement important, ouvrez d'abord une issue afin d'en discuter.
- Ne soumettez jamais de secrets, clés API ou données personnelles.

## Développement local

1. Forkez le dépôt et clonez votre fork.
2. Créez une branche descriptive : `git checkout -b feat/ma-contribution`.
3. Installez les dépendances selon les instructions du `README.md`.
4. Effectuez vos changements et vérifiez qu'ils fonctionnent localement.

## Commits et pull requests

- Utilisez des commits courts et explicites, à l'impératif.
- Gardez chaque pull request ciblée sur un seul sujet.
- Décrivez le problème résolu, les changements réalisés et les tests effectués.
- Ajoutez ou mettez à jour les tests et la documentation lorsque nécessaire.
- Vérifiez que les contrôles automatisés passent avant de demander une revue.

## Revue du code

Les contributions sont examinées selon leur exactitude, leur lisibilité, leur sécurité, leur accessibilité et leur compatibilité avec le projet. Les retours de revue doivent rester constructifs et respectueux.

## Signaler un problème

Utilisez le système d'issues pour signaler un bug ou proposer une amélioration. Incluez une description claire, les étapes pour reproduire le problème, le comportement attendu et, si pertinent, les logs ou captures d'écran en supprimant toute information sensible.

En contribuant, vous acceptez de respecter le [code de conduite du projet](CODE_OF_CONDUCT.md).
